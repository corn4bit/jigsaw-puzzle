Hooking it into your game

The win screen

Puzzle Completion Popup shows the solved level's name and two buttons:

  • Next Level starts the next entry in the library. It hides itself after the last level.
  • Menu goes back to level select.

Both are optional inspector references, and PlayNextLevel() / GoToLevelSelection() are public, so you can wire your own buttons instead.

Puzzle Manager also has Auto Return To Level Selection, which sends the player back on a timer with no popup interaction. It is off by default because the buttons cover the same job; turn it on if you strip the popup down.

Stars and records

A solved level is rated one to three stars on how long it took, and the fastest run is kept. The win screen shows the run just finished; the level card shows the best so far.

Once a level is solved its card shows the record rather than a piece count, because opening it again starts a fresh attempt: the pieces are scattered, the clock restarts, and the stars, the best time and the tick stay as they were. Only a faster run changes them. A level still in progress resumes exactly where it was left.

Each PuzzleLevel has Three Star Seconds and Two Star Seconds. Leave them at 0 and the level works them out from its piece count, four seconds a piece for three stars and twice that for two, which suits most pictures. Set them by hand when a particular level is unusually easy or fiddly.

Replaying counts: a faster run replaces the record, a slower one leaves it alone.

int   stars = PuzzleManager.Instance.GetStars(level);      // best so far, 0..3
double best = PuzzleManager.Instance.GetBestTime(level);   // seconds, 0 if never solved

Inside a completion handler you can also read the run that just ended, through LastRunStars, LastRunTime and LastRunWasRecord.

Hints

The Hint button ghosts one unplaced piece into the slot it belongs in and gives the real piece a nudge. It is free and on a short cooldown out of the box.

To charge for it instead, drop the bundled button and call it yourself:

if (board.HintsUsed >= 3) ShowRewardedAd(onWatched: () => board.ShowHint());
else board.ShowHint();

ShowHint returns false when every piece is already in place, so your own button can disable itself rather than appear to do nothing.

Rewards

Select the Puzzle Completion Popup component and wire its On Level Completed event. It passes the PuzzleLevel that was solved, so a single handler can hand out the right reward for any level:

public void OnPuzzleSolved(PuzzleLevel level)
{
    inventory.Unlock(level.LevelId);
}

From code, without touching the scene:

PuzzleManager.OnPuzzleCompleted += level => Debug.Log($"Solved {level.DisplayName}");
PuzzleManager.OnPuzzleStarted   += level => Debug.Log($"Started {level.DisplayName}");

A handler that throws cannot break the game: the popup still appears and the error is logged.

Starting a level from your own UI

PuzzleManager.Instance.StartPuzzle(myLevel);      // by asset
PuzzleManager.Instance.StartPuzzle("a1b2c3d4…");  // by level id

Either call loads the level's progress and puts the board on screen, so you can run the minigame from your own menu, a shop, a save slot or a cutscene. You do not need the bundled level select screen at all; delete it and the board still works.

Starting a level from code ignores Unlock Mode; it is your menu's job to decide what the player may open. Ask IsUnlocked first if you want the same rule.

Reading progress

bool  done     = PuzzleManager.Instance.IsCompleted(level);
bool  unlocked = PuzzleManager.Instance.IsUnlocked(level);
float progress = PuzzleManager.Instance.GetProgress(level);   // 0..1

Saving

Progress is stored per level and includes where every loose piece is lying, so a player can quit halfway through and come back to the same board.

By default it goes to PlayerPrefs. To route it into your own save system, implement IPuzzleSaveStore and assign it before the first level starts:

PuzzleManager.SaveStore = new MyCloudSaveStore();

Saves are keyed by the level's generated id, not its file name, so renaming a level asset does not lose progress.

Customising

Everything below is on the inspector; none of it needs code.

Board (Puzzle Board)

Setting What it does
Piece Resolution Pixel size of one piece. Raise for sharper pieces on large screens.
Board Screen Fraction How much of the screen the assembled picture takes. The rest is scatter space.
Max Board Scale How far a small grid may be blown up to reach that share.
Scatter Area A RectTransform loose pieces stay inside. Use it to keep pieces off your HUD.
Scatter Above And Below Also scatter above and below the board, not just to the sides.
Relayout On Resize Lay the loose pieces out again when the screen changes shape mid-level, for example when a phone is rotated.
Guide Opacity Opacity of the faint picture under the board. 0 hides it for a harder game.
Border Color Frame drawn around the picture. Alpha 0 gives no frame.
Hint Duration How long a hint stays on the board before fading.
Hint Color Tint of the ghost piece a hint leaves in the empty slot.

Pieces (Puzzle Piece Dragger, on the piece prefab)

Setting What it does
Snap Distance How close two neighbours must be to click together.
Place Tolerance How close to its slot a piece must be to count as solved.
Drag Scale / Drag Alpha How a piece looks while it is being dragged.
Drag Edge Margin Extra inset keeping a dragged piece off the screen edge. Pieces are kept on screen either way.

Sound

Puzzle Audio sits on the Puzzle Manager object and plays five one-shots: picking a piece up, dropping one into place, two pieces clicking together, solving a level and tapping a button. Swap any clip for your own, or clear one to silence that event alone. Delete the component and the minigame runs silently.

Volume and Muted are public, so a settings screen can drive them directly. Every clip goes through one AudioSource, so pointing that source at your own mixer group routes the whole minigame.

The bundled effects in Audio/ were synthesised for this package. They are yours to keep, edit or replace.

Screen shape

The layout follows the canvas rather than a fixed size, so the same prefab works in landscape and portrait:

  • The level list is a scrolling row on a wide screen and a scrolling grid on a tall one. Puzzle Responsive Level List on the Scroll View holds the row height and the column count. On a tall screen the grid fills the space from under its Header (the title) down to Bottom Margin, and Fit Columns To Width stretches the cards so the columns span the whole list. Clear Header to size the grid as a share of the screen instead.
  • Puzzle Responsive HUD on the top bar moves the timer and the piece counter to a second row when they would touch the Back or Preview button, which happens on tall phones held upright. Where they fit, the bar stays as authored.
  • Rotating the device or resizing the window in the middle of a level refits the board and moves the loose pieces into the new free space. Pieces that are already joined move together, and a piece in the player's hand is left alone. The same happens when a level saved on one screen shape is reopened on another, for example saved in landscape and continued upright. Turn Relayout On Resize off on the board to keep pieces where they are.
  • Puzzle Safe Area keeps the HUD and the menu clear of notches and rounded corners. It does nothing on desktop.
  • Max Board Scale on the board decides how far a small grid may be blown up to fill the screen. A 3×3 picture is only 300 units wide, which would leave half a phone screen empty at 1. Raise Piece Resolution if the result looks soft.

Look

The level card, the piece and the whole minigame are ordinary prefabs under Prefabs/. Restyle them however you like: the scripts only need the components they are wired to, and every UI reference is optional.

The backdrop is a single sprite on Content/bg (Art/Background.png). Swap the sprite, or drop your own game's scene behind the canvas and set the image's alpha to zero.

Themes

The palette lives in one asset. Two ship with the package, Midnight and Daylight, under Art/Themes/.

Every element that should follow the palette carries a Puzzle Themed Graphic naming the part it plays: Background, Panel, PanelInset, Title, PanelText, Button, ButtonLabel, Accent, AccentLabel, Star or Progress. The theme decides what colour each of those is. Add the component to images and labels of your own and they change with the rest.

  • To restyle at authoring time: the Style tab, pick a theme, press apply. The colours are written into the prefabs, so the editor shows the result.
  • To switch while the game runs: assign a theme to Puzzle Manager, or set PuzzleManager.Instance.Theme from a settings screen. Everything on screen recolours immediately.

By default each element keeps its own transparency and takes only the colour, which is what lets one Panel colour serve a solid card and a faint overlay. Turn off Keep Alpha on an element whose transparency belongs to the palette instead.

Two things are deliberately not themed: the level card's title and progress text, which sit on top of the player's own picture rather than on a themed surface, and a piece, which is the picture. Leave a theme unassigned and nothing is recoloured at all.

Fonts

The package ships with Fredoka SemiBold, under the SIL Open Font License. Its licence text sits next to it in Art/Fonts/. Keep the two together if you redistribute the font.

To use your own instead: the Style tab, drop a font in and press apply. Every label across the minigame and the level cards switches at once: counters, timer, buttons, win popup. The same tab puts Unity's built-in font back if you would rather ship no font at all.

How the cutting works

  1. The picture is rescaled to exactly columns × pieceSize by rows × pieceSize. This is why any source resolution and aspect ratio works.
  2. A border is added so the tabs of the outer pieces have room.
  3. Each piece gets four edges. Edges shared with an already-cut neighbour are mirrored so they interlock; the outside of the picture is straight; the rest are random, so the same level looks different every time it is played.
  4. Each piece is flood-filled from its centre out to its outline and copied from the source pixels.

All of it runs on the CPU through Color32[], one piece per frame, so a large grid never stalls the game.

Performance notes

  • Cutting is spread across frames: a 10×10 grid takes about 100 frames to appear.
  • Piece textures are pieceResolution + 2 × border square, RGBA32. At the default 100 px that is roughly 78 KB per piece.
  • Every runtime texture and sprite is destroyed when the level unloads.
  • Saves are batched and written at most once per second, never per drag frame.

Package layout

Corn4Bit/JigsawPuzzle/
├── Runtime/          Game code (assembly: Corn4Bit.JigsawPuzzle)
│   ├── Core/         Levels, progress, save system
│   ├── Generation/   Picture rescaling and piece cutting
│   ├── UI/           Board, pieces, HUD, level select
│   ├── Theming/      Theme asset and the tag component
│   └── Tweening/     Built-in animation system
├── Editor/           Level wizard, font tool, inspectors, scene doctor
├── Prefabs/          The minigame, a level card, a piece
├── Art/              UI sprites, themes and the bundled font
├── Audio/            Sound effects
├── Demo/             Demo scene, levels and images
└── Documentation/    This file

Nothing lives outside this folder, and the package references nothing outside it. Every sprite, sound, the font and all code live inside it, and it pulls in no other package. Delete Demo/ once you have your own levels.
