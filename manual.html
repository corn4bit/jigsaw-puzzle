Hooking it into your game

The win screen

Puzzle Completion Popup shows the solved level's name and two buttons:

  • Next Level starts the next entry in the library. It hides itself after the last level.
  • Menu goes back to level select.

Both are optional inspector references, and PlayNextLevel() / GoToLevelSelection() are public, so you can wire your own buttons instead.

The popup opens over a dimmed screen (WinPanel/Dim), with a soft glow behind the panel and a burst of stars flying out from behind it. Both are set in the popup's Celebration section: Panel Body (the background they sit behind), Glow Sprite and Glow Color, Sparkle Sprite and Sparkle Count. Clear a sprite to drop that effect. The board adds a light flash of its own, Flash Opacity on Puzzle Board, which 0 turns off.

The popup waits Admire Delay (1 second) after the last piece lands, so the player sees the finished picture whole before it is covered. While it is up, everything in Fade While Shown (in the demo: the HUD buttons, booster bar, piece tray and reroll) drops to Faded Alpha and stops taking taps, so nothing behind it looks clickable. On a wide screen, where the board sits on the left, the popup moves right so the finished picture stays in view (Wide Shift, and down by Wide Drop so the coin plaque clears its ribbon). On a tall screen it stays centred.

Puzzle Manager also has Auto Return To Level Selection, which sends the player back on a timer with no popup interaction. It is off by default because the buttons cover the same job; turn it on if you strip the popup down.

Target Frame Rate on Puzzle Manager (60 by default) asks for 60 frames per second. Phones otherwise hold a Unity game at 30, which makes dragging pieces and scrolling the map feel sluggish. Set it to 0 to keep the platform's default, or raise it for high refresh screens; it has no effect where V Sync is on in the Quality settings.

Stars and records

A solved level is rated one to three stars on how long it took, and the fastest run is kept. The win screen shows the run just finished; the level card shows the best so far.

Once a level is solved its card shows the record rather than a piece count, because opening it again starts a fresh attempt: the pieces are scattered, the clock restarts, and the stars, the best time and the tick stay as they were. Only a faster run changes them. A level still in progress resumes exactly where it was left.

Each PuzzleLevel has Three Star Seconds and Two Star Seconds. Leave them at 0 and the level works them out from its piece count, four seconds a piece for three stars and twice that for two, which suits most pictures. Set them by hand when a particular level is unusually easy or fiddly.

Replaying counts: a faster run replaces the record, a slower one leaves it alone.

int   stars = PuzzleManager.Instance.GetStars(level);      // best so far, 0..3
double best = PuzzleManager.Instance.GetBestTime(level);   // seconds, 0 if never solved

Inside a completion handler you can also read the run that just ended, through LastRunStars, LastRunTime and LastRunWasRecord.

Hints

The Hint button picks the piece that helps most (the one with the most neighbours already in place, otherwise an edge piece) and rings both it and its slot in a soft gold glow that follows the piece's outline. The glow stays until the piece is placed or six seconds pass (Hint Duration), and pressing the button again while it is up costs nothing.

Hints are free unless something says otherwise. The board asks CanShowHint before each new one, so charging for them is one line:

board.CanShowHint = () => wallet.TrySpend(hintCurrency, 1);

With the meta game in the scene, Puzzle Hint Supply on the button does exactly that from the player's hint stock (see Hints and boosters below). ShowHint returns false when there is nothing to hint or the gate refused, so your own button can react.

Rewards

Select the Puzzle Completion Popup component and wire its On Level Completed event. It passes the PuzzleLevel that was solved, so a single handler can hand out the right reward for any level:

public void OnPuzzleSolved(PuzzleLevel level)
{
    inventory.Unlock(level.LevelId);
}

From code, without touching the scene:

PuzzleManager.OnPuzzleCompleted += level => Debug.Log($"Solved {level.DisplayName}");
PuzzleManager.OnPuzzleStarted   += level => Debug.Log($"Started {level.DisplayName}");

A handler that throws cannot break the game: the popup still appears and the error is logged.

Starting a level from your own UI

PuzzleManager.Instance.StartPuzzle(myLevel);      // by asset
PuzzleManager.Instance.StartPuzzle("a1b2c3d4…");  // by level id

Either call loads the level's progress and puts the board on screen, so you can run a level from your own menu, a shop, a save slot or a cutscene. You do not need the bundled level select screen at all; delete it and the board still works.

Starting a level from code ignores Unlock Mode; it is your menu's job to decide what the player may open. Ask IsUnlocked first if you want the same rule.

Reading progress

bool  done     = PuzzleManager.Instance.IsCompleted(level);
bool  unlocked = PuzzleManager.Instance.IsUnlocked(level);
float progress = PuzzleManager.Instance.GetProgress(level);   // 0..1

Meta game

Around the puzzle runs a meta game: currencies the player earns and spends, and boosters they own. It lives in its own assembly, Corn4Bit.JigsawPuzzle.Meta, and only listens to the puzzle, so the puzzle code is the same with or without it.

Everything is data. Data/Meta/Meta Config lists the game's currencies and boosters; balancing the economy means editing those assets, never code.

Asset What it holds
Puzzle Currency Id, name, icon, starting amount and an optional cap. The demo has Coins (200 to start) and Gems (10).
Puzzle Booster Id, name, one line of description, icon, whether it is used before or during a level, price and starting stock. The demo has Magnet, Frame, Stopwatch, Ready Edge and Double Coins, two of each to start.
Puzzle Meta Config The lists of both, assigned to the Puzzle Meta component next to the Puzzle Manager.

From code, through PuzzleMeta.Instance:

PuzzleMeta meta = PuzzleMeta.Instance;
PuzzleCurrency coins = meta.Config.FindCurrency("coins");

meta.Wallet.Add(coins, 50, "daily");             // pays, up to the currency's cap
bool paid = meta.Wallet.TrySpend(coins, 150);     // false and untouched when short
bool bought = meta.Inventory.TryBuy(meta.Config.FindBooster("magnet"), meta.Wallet);
bool used = meta.Inventory.TryUse(meta.Config.FindBooster("magnet"));

Balances never go below zero or above their cap, and buying takes the money and delivers the booster in one step. Every change raises a static event on PuzzleMetaEvents (CurrencyChanged, BoosterChanged, with the new amount, the change and a reason string), and so does every solved level (LevelCompleted). Screens and analytics listen there instead of polling.

The meta progress is saved through the same IPuzzleSaveStore as the levels, under the key corn4bit.meta, so routing saves to the cloud covers both. A new player gets the starting amounts once; PuzzleMeta.ResetProgress() starts over.

A currency or booster added to the config in a later update is handed its starting amount on the player's next run, once, so existing players do not start it at zero.

Menu shell

The level select screen is one of five tabs: Shop, Ranks, Home, Friends and Profile, with Home, the level map, in the middle.

  • Puzzle Tab Bar runs along the bottom of a tall screen and down the left of a wide one, swapping over when the device turns. The selected tab rises onto a blue tile with its name under it; the others sit muted. Screens slide sideways when the tab changes and are only switched off, never rebuilt, so the map keeps its place. Each tab can carry a red badge with a count (SetBadge("shop", 3)), and Select(id) opens a tab from code. Shop, Ranks, Friends and Profile are placeholder screens that later updates fill.
  • Puzzle Feature Gate opens features as the player progresses. The rules live in the meta config's Features list: by default Ranks opens at level 5 and Friends at level 10. A locked tab wears a padlock, and tapping it shakes the icon and says which level opens it. Untick Enabled to remove a feature entirely.
  • Puzzle Top HUD holds the avatar, one Puzzle Currency Plaque per currency and the settings button. Plaques follow every balance change, roll the number up and bounce the icon when it rises, and their plus button opens the shop. On a tall phone the avatar steps aside (the Profile tab does the same job) and the plaques shrink to fit rather than overlap.
  • Puzzle Loading Screen covers the menu for a moment while the game opens: logo, title and a filling bar, then a fade. Minimum Duration sets how long it stays.

The demo has three currencies on the HUD: Hints (5 to start), Coins and Gems.

Level rewards

A solved level pays coins, and the win popup shows them arriving.

  • Puzzle Reward Table (Data/Meta/Reward Table, assigned to the meta config's Rewards) sets the pay: by default 10, 20 or 30 coins for a one, two or three star run, doubled the first time a level is solved, so new levels always pay better than replaying old ones. The currency, the three amounts and the multiplier are all fields. Leave Rewards empty and levels pay nothing.
  • Puzzle Reward Flight on the win popup plays the payout: the amount counts up in a coin row under the stars, an x2 badge stamps on for a first clear, then coins fan out of the row and fly into a coin plaque that drops in at the top of the screen. The plaque's number rises as each coin lands, with a chime. Closing the popup early puts the rest on the plaque at once, so the count is never left short. Its Hide While Shown list hides the level's own timer and counter, which the plaque would otherwise cover, and brings them back afterwards.

The money is in the wallet before the popup opens; the flight only replays the moment. PuzzleMetaEvents.LevelRewarded reports each payout with its level, stars, amount and multiplier, and PuzzleMeta.Instance.PayForLevel(level, stars, firstClear) pays for a level solved somewhere other than the Puzzle Manager.

Hints and boosters

Hint stock. Hints are a currency (Hints, 5 to start) that refills by itself: one every 20 minutes while the stock is under 5, counted in real time, so hints come back while the game is closed too. Purchases and rewards can push it past 5; the timer waits until it drops back under. The settings live in the meta config: Hint Currency, Regeneration (cap and minutes, for any currency, not just hints) and the out-of-hints offer (Hint Refill Amount, price and currency: 3 for 150 coins by default). The hint plaque on the map shows the wait for the next one, or Full.

In a level, Puzzle Hint Supply on the Hint button puts a badge with the stock on it (a plus at zero). With none left, a tap opens the offer instead, saying when the next free one comes back. PuzzleMeta.Clock is the time source for the refill, so a game that does not trust the device clock can plug in its server's.

Boosters. Each Puzzle Booster now says what it does (Effect) and how strongly (Power), so the five in the demo work with no code:

Booster When Effect Power
Magnet in level PlacePieces: flies pieces from the tray straight into place 3 pieces
Frame in level DealEdges: deals the edge pieces into the tray next
Stopwatch in level StopClock: stops the level clock, so the stars wait 30 seconds
Ready Edge level start BuiltBorder: the border flies into place as the level opens
Double Coins level start MultiplyReward: multiplies the level's coin reward x2

Custom does nothing itself: listen to PuzzleMetaEvents.BoosterUsed and do your own thing. A booster that would do nothing right now, such as a magnet on a board with no pieces left, is not taken.

  • Puzzle Booster Bar holds the in-level boosters, one Puzzle Booster Slot each: icon, count badge, padlock until it opens. It sits halfway between two buttons you name per screen shape (reroll and hint along the bottom of a tall screen, preview and reroll down the side of a wide one), spaced evenly and shrunk if the gap is tight. The stopwatch slot counts its seconds down while the clock is stopped.
  • Puzzle Level Start Popup opens when the player picks a level: number, name, picture, best stars and time, the level start boosters to tick, and Play. It takes over through PuzzleLevelSelectionUI.InterceptStart, so the map and cards are unchanged, and without the meta levels start straight away.
  • Puzzle Purchase Popup is the mini shop for all of it: at zero, a booster or hint is offered for coins on the spot, without leaving the level. The level clock stops while it is open.
  • Puzzle Tutorial Pointer is a tapping finger with a speech bubble. The first time each booster is open and on screen, it points at it with the booster's description, one booster at a time. It never blocks input; tapping the booster closes it.
  • Boosters open as the player progresses, through the same feature list as the tabs (booster.magnet and so on): by default Magnet at level 2, Frame 3, Stopwatch 4, Ready Edge 5 and Double Coins 6. Every player starts with two of each.

From code: PuzzleMeta.Instance.UseBooster(booster), ArmForLevel(level, boosters), TrySpendHint(), BuyHintRefill() and SecondsToNextRefill(currency).

Hooks added to the puzzle for this, each usable on its own: PuzzleBoard.CanShowHint, PlacePieces, UnplacedPieces, IsEdge and the static Built event; PuzzlePieceTray.Release and Prioritise; PuzzlePieceDragger.FlyHome; PuzzleSession.ClockPaused; PuzzleAudio.PlayClip.

Shop

The Shop tab sells from Data/Meta/Shop Catalog (assigned to the meta config's Shop). Each Puzzle Shop Item names its section, what it gives (currencies and boosters, any mix), and how it is paid for: a store Sku for real money, a currency and price, or nothing for a free gift. Optional: a badge (Best value), a crossed-out old price, a purchase limit, an offer that ends some hours after the player first sees it, and a cooldown for gifts.

The demo catalog: a one-time Starter Pack (48 hours, -80%), two bundles, three gem packs, three coin packs bought with gems, and a free 50 coins every 4 hours.

  • Puzzle Shop Screen lays the catalog out in sections under ribbon headings, the special offer full width and the rest in rows that refit when the screen turns. On a wide screen two sections stand side by side whenever they fit (Section Gap), so the landscape shop fills the screen instead of running down a narrow column.
  • Puzzle Shop Card shows one item: picture, amount, price button (with the currency's icon when it costs coins or gems), badge, old price, time left on a small pill with a clock (Timer Badge), sold out. A special offer lists everything it gives, each with its icon and amount (Contents Row, Content Template), shrinking as one piece if the line is longer than the card.
  • Puzzle Reward Popup shows what was bought, spacing the entries so long amounts such as "x1 000" never touch and shrinking a long row to fit the window; on Claim the coins and gems fly into their top HUD plaques (Puzzle Coin Flight, usable for any reward).

Real money goes through IPuzzlePurchaseProvider, assigned to PuzzleMeta.Purchases. Out of the box it is PuzzleDemoPurchaseProvider, which hands everything out without charging, and the shop says so on screen. Plug in Unity IAP or any store by implementing three members:

public class MyStore : IPuzzlePurchaseProvider
{
    public bool IsDemo => false;
    public string GetPrice(string sku) => /* the store's localised price */;
    public void Purchase(string sku, Action<bool> done) => /* call done(true) once paid */;
}

PuzzleMeta.Purchases = new MyStore();

Free gifts can be put behind a rewarded ad the same way: set PuzzleMeta.Ads to your IPuzzleAdsProvider. Without one, a gift is simply claimed when its timer allows. From code: PuzzleMeta.Instance.Buy(item, done), ClaimGift, StateOf, PriceLabel, and PuzzleMetaEvents.ItemPurchased for analytics.

Profile and settings

The Profile tab shows the player's avatar in its frame, their name (tap to edit, up to 16 characters), and four totals read from the saves: levels solved, stars, fastest solve and days in a row (counted each day the game is opened, back to 1 after a missed day). On a tall screen the card is only as high as its column (Tall Card Height) and sits centred; on a wide one avatar and totals stand side by side.

  • Data/Meta/Avatar Set (assigned to the meta config's Avatars) holds the avatars, all free, and the frames: blue and green free, gold for 50 gems and purple for 100. The demo avatars are twelve chip characters, each with its own colour and accessory.
  • Puzzle Avatar Picker chooses among them; a locked frame shows its price and buying it wears it. The picker scales itself down to fit a short landscape screen, ribbon and close button included (Overhang, Side Overhang), and refits when the screen turns. Puzzle Avatar View shows the current avatar and frame anywhere, the top HUD's avatar included, and follows every change.
  • Puzzle Settings Window opens from the HUD's gear: sound, music and vibration switches (Puzzle Switch) and a quiet Reset progress link, which asks first in a Puzzle Confirm Popup with a red button. A language row is in the prefab but switched off (LanguageRow) until the game has more than one language. The reset wipes every level and the whole meta (PuzzleMeta.Instance.ResetEverything()).

Settings are saved with the meta. Sound drives Puzzle Audio's mute; music is a flag for your music player to read (PuzzleMeta.Instance.Profile.musicOn), and PuzzleMeta.Vibrate() buzzes a phone only when vibration is on.

Leaderboard

The Ranks tab (open from level 5) has three boards: Stars (most stars), Level time (fastest solve of the level being played, or the furthest one solved) and Level (furthest level reached). Each row shows the place, with gold, silver and bronze medals for the top three, the avatar in its frame, the name and the score. The player's own row is highlighted, and pinned to the bottom of the list while it is scrolled out of sight; the list then ends above the pinned row (Pinned Gap) instead of running under it. On a wide screen the board keeps to a readable width (Puzzle Max Width on its Column).

Out of the box the boards are filled by PuzzleBotLeaderboard: fifty bots with ready-made names and scores spread round the player's own, densest near it, so there is always someone just ahead to beat. The field is the same all week and changes with the next, so the list does not reshuffle each time the tab opens.

For real players, implement one method over your backend and assign it:

public class MyBoards : IPuzzleLeaderboardProvider
{
    public void Fetch(PuzzleLeaderboardBoard board, PuzzleLevel level,
                      PuzzleLeaderboardEntry player, Action<List<PuzzleLeaderboardEntry>> done)
    {
        // Submit player.score, download the top, put the player at their place, then:
        done(entries);
    }
}

PuzzleMeta.Leaderboards = new MyBoards();

Puzzle Leaderboard Screen and Puzzle Leaderboard Row draw whatever the provider returns. PuzzleMeta.Instance.PlayerEntry(board, level) gives the player's own score for any board.

Friends

The Friends tab (open from level 6 in the demo) lists the player's friends, furthest first: avatar in its frame, name, level reached, and a Send button for a free daily gift. Gifts friends sent today wait in a block at the top with Claim all, which pays 50 coins each (the meta config's Gift Currency and Gift Amount) and sends them flying into the coin plaque. Invite friends shares the config's Invite Message. With no friends at all the tab shows an empty state with an Invite button instead. On a wide screen the list keeps to a readable width (Puzzle Max Width on ListArea).

Puzzle Max Width is a small layout helper you can put on any stretched panel: it fills the width on a phone and stops at Max Width, centred, on a wider screen.

Out of the box PuzzleBotFriends gives the player eight bot friends at levels round their own, a few of whom send a gift each day, and invites are copied to the clipboard (PuzzleClipboardShare). Plug in the real thing through two interfaces:

PuzzleMeta.Friends = new MyFriends();   // IPuzzleFriendsProvider: GetFriends, GetGiftsSent, SendGift
PuzzleMeta.Share = new MyShareSheet();  // IPuzzleShareProvider: Share(message, done)

Sending and claiming are tracked per friend per day in the meta save, so a gift can be sent once a day to each friend and each friend's gift claimed once.

Daily reward and chapter chests

Daily reward. A seven-day calendar opens by itself on the first visit of the day (Puzzle Daily Reward Popup): today's day pulses, days already claimed carry a tick, and Claim pays the day and flies it into the plaques. Claiming every day walks through the week; a missed day, or the end of the week, starts again at day 1. Rows of the calendar are centred, and a day marked Big takes two cells so the week ends on its best reward. Each day's icon grows with its card. Opened over a level, the calendar stops the level clock until it closes. The demo week: 50 and 75 coins, 2 hints, 100 coins, a magnet, 5 gems, and a big seventh day of 300 coins, 10 gems and two boosters. Set the days in the reward table's Daily Rewards.

Chapter chests. Every chapter banner on the map carries a chest with the chapter's stars, such as 5/9 (Puzzle Chapter Chests, on the level map). Once every star of the chapter is earned the chest wiggles; a tap opens it for 100 coins and a random booster (Chest Contents, Chest Boosters) with a little hop. A tap on a chest that is not full yet shakes it; an opened chest stays open and ignores taps. Levels Per Chapter in the reward table must match the map's zone sizes, 3 in the demo. The map raises BannerShown(banner, index) for anything else you want to hang on a banner.

From code: PuzzleMeta.Instance.DailyDayToClaim(), ClaimDaily(), ChapterStars(chapter, out earned, out total), ChestReady(chapter) and OpenChest(chapter).

Any Puzzle Currency Plaque can show a reward arriving: Hold(amount) keeps that much of the balance off the display, Release(amount) lets part of it in with a roll and a bounce, and ReleaseAll() lets in the rest.

The package ships EditMode tests for all of this in Tests/. They compile only in a project that has Unity's Test Framework package, so they cost nothing elsewhere.

Saving

Progress is stored per level and includes where every loose piece is lying, so a player can quit halfway through and come back to the same board.

By default it goes to PlayerPrefs. To route it into your own save system, implement IPuzzleSaveStore and assign it before the first level starts:

PuzzleManager.SaveStore = new MyCloudSaveStore();

Saves are keyed by the level's generated id, not its file name, so renaming a level asset does not lose progress.

Customising

Everything below is on the inspector; none of it needs code.

Piece tray (Puzzle Piece Tray)

By default the loose pieces wait in a tray: a few at a time on a shelf under the board on a tall screen and beside it on a wide one, the rest queued out of sight. The board comes first: it keeps the full width of a tall screen and the full height of a wide one, and the tray grows its slots as large as what is left allows, in one row or two, every piece is in reach of a thumb, and a 100 piece level is no messier than a 9 piece one. Drop a piece near its place and it goes in; drop it anywhere else and it slides back to its slot. Each placed piece is replaced from the queue. What the tray shows and the order of its queue are saved with the level.

Setting What it does
Slot Count How many pieces are on show at once.
Max Slot Size Largest a slot may grow. Slots go into two rows when that makes them larger without shrinking the board.
Piece Fill / Spacing How much of a slot the picture part of a piece fills (its tabs reach a little further), and the gap between slots. Pieces are shown this large however small they are on the board, so even a 100 piece level is easy to read, and shrink to their board size when picked up.
Piece Shadow Soft shadow under the pieces on the shelf. Alpha 0 turns it off.
Hud Top, Edge Margin, Tall Bottom, Wide Right, Board Gap Room kept clear for the HUD and the corner buttons, and the gap between tray and board.
Order Smart favours edges and pieces that fit next to what is already placed, with some chance mixed in. Random is a plain shuffle.
Look Ahead Smart order: how many waiting pieces it picks among. Lower is more predictable.
Reroll Button Swaps the pieces on show for others. Placed in the row of corner buttons (bottom left when upright, above the hint button when sideways) so it never takes a slot's room. Set CanReroll from code to charge for it.

From code: PuzzleBoard.RerollTray(), PuzzleBoard.PieceTray, and on the tray Remaining, Showing, CanReroll and the Rerolled event.

Prefer the classic way? Set Piece Layout on Puzzle Board to Scatter and the pieces are spread around the board as before, joining each other wherever they meet.

Board (Puzzle Board)

Setting What it does

Piece Resolution Pixel size of one piece. Raise for sharper pieces on large screens.
Board Screen Fraction How much of the screen the assembled picture takes. The rest is scatter space.
Max Board Scale How far a small grid may be blown up to reach that share.
Scatter Area A RectTransform loose pieces stay inside. Use it to keep pieces off your HUD.
Scatter Above And Below Also scatter above and below the board, not just to the sides.

Pieces (Puzzle Piece Dragger, on the piece prefab)

Setting What it does
Snap Distance How close two neighbours must be to click together.
Place Tolerance How close to its slot a piece must be to count as solved.
Drag Scale / Drag Alpha How a piece looks while it is being dragged.
Drag Edge Margin Extra inset keeping a dragged piece off the screen edge. Pieces are kept on screen either way.
Lift Above Finger Touch Only (default) floats a dragged piece above the finger on touch screens so the finger does not hide it; Always does the same for the mouse, Off keeps the piece exactly under the pointer. The piece is dropped where it is drawn.

Streak praise (Puzzle Combo Praise, over the board)

Pieces dropped straight into their slots one after another build a streak, and the game cheers it on: Good! at 2, Great! at 3, Awesome! at 5, Amazing! at 7, Incredible! at 10, then Unstoppable! every 3 more. The word pops over the board with a burst of sparks and a chime. A drop anywhere else, or a pause longer than Streak Window (10 seconds), starts the count again; the piece that finishes the level is left to the win screen.

Setting What it does
Tiers The ladder: streak, word and colour of each step. Add, remove or rename freely.
Endless Text / Repeat Every What shows past the last tier, and how often.
Streak Window Seconds allowed between placements. 0 never times out.
Anchor To The word pops over the centre of this; the demo uses the board's piece container.
Spark Sprite, Spark Count, Spark Size, Sound The burst and the chime. Clear them for a quieter praise.

PuzzleComboPraise.Praised(streak, word) is raised each time, for example to pay a coin per praise, and PuzzlePieceDragger.Landed(piece, solved) reports every drop if you want your own streak rules. Show(word, colour) pops a word on demand.

Sound

Puzzle Audio sits on the Puzzle Manager object and plays five one-shots: picking a piece up, dropping one into place, two pieces clicking together, solving a level and tapping a button. Swap any clip for your own, or clear one to silence that event alone. Delete the component and the game runs silently.

Volume and Muted are public, so a settings screen can drive them directly. Every clip goes through one AudioSource, so pointing that source at your own mixer group routes the whole game.

The bundled effects in Audio/ were synthesised for this package. They are yours to keep, edit or replace.

Level map (Puzzle Level Map)

The demo's level select screen is a map: a winding road with one round node per level, the picture inside the node, its number on a badge, stars above it and a lock until it opens. The road is coloured up to the level the player is on, which also wears a pulsing ring, and the map scrolls there by itself whenever the player comes back from a level.

Nothing on the map is placed by hand. The road, the nodes and the backdrops are worked out from the level count, so adding a level to the library puts it on the map. Only the nodes on screen exist; they are recycled as the map scrolls, so a thousand levels cost the same as ten.

Setting What it does
Direction Auto climbs upwards on a tall screen and runs sideways on a wide one, and changes over when the device turns. Upwards and Sideways fix it.
Node Spacing Distance between two levels along the road.
Swing / Max Swing How far the road bends to either side, as a share of the map and as a cap in canvas units.
Levels Per Wave How many levels one full bend of the road takes.
Start Padding / End Padding Empty map before level 1 and after the last level.
Header Space Strip kept clear for the title on a sideways map.
Focus Point Where the current level settles on screen, from the start of the road (0) to the end (1).
Zones Stretches of the map with their own tint, backdrop picture and banner title, each holding a set number of levels. They repeat once the levels outnumber them, so three zones serve a map of any length.
Zone Blend How far neighbouring zones overlap, so they fade into each other instead of meeting at a line.

The pieces it uses are all in the prefab and all optional:

  • Node Prefab (Prefabs/PuzzleLevelNode) is a Puzzle Level Button, the same component the cards use, with a Number Text for the badge. Restyle it freely. Its State Looks swap the ring (Frame Image) and the number badge (Badge Image) by state: locked, open, current (the level the player is up to) and solved, each with its own number outline colour. The bundled looks are green for solved, blue for open, gold for current and cream with a gold padlock for locked. Leave a sprite empty to keep whatever the image already shows.

  • Path is a Puzzle Map Path, a mesh with no art behind it: road width, edge, dashes and the colours of the road ahead and behind. With Follow Theme on it takes those colours from the active theme.

  • Current Marker is any image; it is moved onto the current level and pulses. The bundled one is a soft gold glow behind the node.

  • Zone Template is a Puzzle Fade Graphic, a rectangle that fades out at its ends. A Text inside it becomes the zone's banner. With Repeat Picture on, a zone's backdrop keeps its proportions and repeats along the road instead of stretching. With Mirror Copies on (the default) every other copy is mirrored, so the joins match even on art that was not made to tile; keep anything distinctive away from the picture's edges, or it meets its own reflection. Turn it off for a picture that tiles by itself and has an up and a down, such as trees drawn from the side, or every other copy stands upside down.

  • The demo's chapters share one backdrop, Art/UI/bg_chapter_meadow.png: sunny candy grass with clover and tiny flowers and nothing tall on it, so the road can wind anywhere. It tiles seamlessly, so the template repeats it without mirroring. Each chapter tints it slightly (Color on the zone). The zones reach past the map (Overscan past its ends, Side Overscan past its sides) and the viewport's RectMask2D padding is widened to match, so the meadow fills the screen up under the top HUD and down under the tab bar.

  • Map Scenery (Puzzle Map Scenery, next to the map) stands trees, bushes, flowers, rocks, a cottage, a pond, a well and the rest around the road, never on it and never under a node or a chapter banner. The map is split into a grid (Cell Size) and every cell decides what stands in it from its own coordinates, so the same map always looks the same, a long map costs nothing up front and only the cells near the screen are built. Each object in Items belongs to a band beside the road: Grove far from it, where the trees gather, Clearing in the open meadow, and Roadside right by the road for small things. Landmark keeps the neighbouring cells empty, for a house or a pond that should stand on its own; Sway rocks it gently in the wind; Flip lets it show mirrored for variety. Density, the band distances, the room kept around the road and the nodes, and Seed shape the whole layout. Objects lower on the screen stand in front, each with a soft contact shadow. The layout follows the road in both orientations and is rebuilt when the screen turns. Sunlight comes through the leaves: some grove trees (Ray Chance) let a ray of sun slant down from under their leaves onto the grass, where it lights a warm patch. Every ray leans the same way (Sun Angle), as from one sun, slowly brightens and dims (Ray Pulse), and belongs to the world, so it scrolls with the map. The demo scenery (Art/Map) was generated with Recraft and cut into sprites; swap in your own pictures in Items.

  • Map Ambience (Puzzle Map Ambience, next to the map) keeps the meadow alive: a warm glow can tint the corner of the screen the sun comes from, and a fan of rays can fall from it (Sunlight; the demo keeps only a faint glow and lets the scenery's rays carry the light, since rays fixed to the screen look odd as the map scrolls under them), faint cloud shadows drift across the grass, butterflies wander over the map and sparkles wink on and off. The sunlight belongs to the screen and stays put while the map scrolls; everything else moves with the map and is only kept around the part on screen, so a long map costs the same few images. Counts, sizes, speeds, colours and the sparkle rate are on the component; leave a sprite empty to switch that effect off. Shadows and sparkles stay under the road and the nodes, butterflies fly above them, and none of them catch taps.

From code, FocusLevel(index, animate) scrolls to any level and CurrentIndex says which one the player is up to.

Prefer the card list? Clear Level Map on Puzzle Level Selection UI, switch off the LevelMap object and switch on Scroll View. The cards come back exactly as before, with everything under Screen shape below.

Screen shape

The layout follows the canvas rather than a fixed size, so the same prefab works in landscape and portrait:

  • The level map runs sideways on a wide screen and upwards on a tall one (see Level map above). If you use the card list instead, it is a scrolling row on a wide screen and a scrolling grid on a tall one. Puzzle Responsive Level List on the Scroll View holds the row height and the column count. On a tall screen the grid fills the space from under its Header (the title) down to Bottom Margin, and Fit Columns To Width stretches the cards so the columns span the whole list. Clear Header to size the grid as a share of the screen instead.
  • Puzzle Responsive HUD on the top bar moves the timer and the piece counter to a second row when they would touch the Back or Preview button, which happens on tall phones held upright. Where they fit, the bar stays as authored.
  • Rotating the device or resizing the window in the middle of a level refits the board and moves the loose pieces into the new free space. Pieces that are already joined move together, and a piece in the player's hand is left alone. The same happens when a level saved on one screen shape is reopened on another, for example saved in landscape and continued upright. Turn Relayout On Resize off on the board to keep pieces where they are.
  • Puzzle Safe Area keeps the HUD and the menu clear of notches and rounded corners. It does nothing on desktop.
  • Max Board Scale on the board decides how far a small grid may be blown up to fill the screen. A 3×3 picture is only 300 units wide, which would leave half a phone screen empty at 1. Raise Piece Resolution if the result looks soft.

Look

The level card, the map node, the piece and the whole game are ordinary prefabs under Prefabs/. Restyle them however you like: the scripts only need the components they are wired to, and every UI reference is optional.

The backdrop is a single sprite on Content/bg (Art/UI/bg_navy.png, kept under its old name: a berry violet gradient with sunlight from the top, a faint jigsaw pattern and soft bokeh; the level has a calmer one, bg_board.png). Swap the sprite, or drop your own game's scene behind the canvas and set the image's alpha to zero. bg_slate is there for plainer service screens.

The art follows one recipe throughout, so additions can match it:

  • Three planes by lightness: a dark or saturated backdrop, saturated containers with cream insets, and the brightest colours and gold reserved for what the player acts on.
  • Windows and main buttons sit in a thick gold bezel; small buttons inside a panel do not.
  • Objects (coins, gems, boosters, tab icons) have no thick outline. Each part has a fine edge in its own darker tone, light at the upper left, a core shadow with reflected light at the lower right, and flat parts have real thickness: a solid wall under the face.
  • Highlights are a soft spot and one or two crisp points, never a white sheet.
  • Buttons squash under the finger and spring back on release (Puzzle Button Press, on every button in the prefab; add it to your own). Small buttons keep a hit area of at least 96 canvas units through Raycast Padding, about 48 dp on a phone, and a tap anywhere on a currency plaque in the HUD works like its plus.
  • Windows pop in from 80% to 105% and settle at full size in 0.3 seconds (PuzzleWindowAnimation.PopIn), over a deep violet dim (#3A2A55 at 55%).

The tab bar's look is set on the Puzzle Tab Bar: Active Lift, Active Scale and Idle Scale for the icons, Tile Raise for the selected tile, Thickness and Edge Margin for the bar itself. Bottom Padding keeps the tabs and the label off the bottom edge on tall screens, on top of the phone's safe area (home indicator); the bar's background still runs to the edge. The selected tile never slides past the screen's side.

Themes

The palette lives in one asset. Three ship with the package under Art/Themes/: Candy, which the demo uses and which leaves the art's own colours untouched, and Midnight and Daylight, which tint it.

Every element that should follow the palette carries a Puzzle Themed Graphic naming the part it plays: Background, Panel, PanelInset, Title, PanelText, Button, ButtonLabel, Accent, AccentLabel, Star or Progress. The theme decides what colour each of those is. Add the component to images and labels of your own and they change with the rest.

  • To restyle at authoring time: the Style tab, pick a theme, press apply. The colours are written into the prefabs, so the editor shows the result.
  • To switch while the game runs: assign a theme to Puzzle Manager, or set PuzzleManager.Instance.Theme from a settings screen. Everything on screen recolours immediately.

By default each element keeps its own transparency and takes only the colour, which is what lets one Panel colour serve a solid card and a faint overlay. Turn off Keep Alpha on an element whose transparency belongs to the palette instead.

Two things are deliberately not themed: the level card's title and progress text, which sit on top of the player's own picture rather than on a themed surface, and a piece, which is the picture. Leave a theme unassigned and nothing is recoloured at all.

Text outline (Puzzle Text Outline)

Headings, counters and button captions carry a Puzzle Text Outline instead of Unity's Outline and Shadow. Unity's Outline copies the text four times along the diagonals, so the edge comes out thick at the corners and thin on straight strokes, which shows badly on round digits. This one spreads its copies round a circle for an even edge and draws a solid drop shadow under the outlined text in the same pass.

Setting What it does
Outline Color / Width Colour and thickness of the edge. 0 width draws none.
Directions Copies around the circle. Raise it on very thick outlines.
Shadow Color / Shadow Distance The lip under the text. 0 distance draws none.
Face Gradient / Face Top / Face Bottom Paints each letter top to bottom with two colours, cream by default, over the text's own colour. The outline and shadow are left alone. From code: SetFaceGradient(top, bottom).

The house style: headings, buttons and numbers in Lilita One with the cream face gradient and an outline in the darkest tone of whatever they sit on (dark green on a green button, dark berry on the pink ribbon, dark blue on blue). Dark navy text with no outline on cream.

Add it to any Text of your own; it follows the text's transparency, so fading a label fades its outline too.

Fonts

The package ships with two fonts, both under the SIL Open Font License, each with its licence text next to it in Art/Fonts/. Keep each font with its licence if you redistribute it.

  • Lilita One: headings, buttons and numbers. Heavy and compact, it reads at a glance.
  • Fredoka SemiBold: running text up to about 36 px, such as descriptions and the tutorial bubble.

To use your own instead: the Style tab, drop a font in and press apply. Every label across the game, the level cards and the map nodes switches at once: counters, timer, buttons, win popup. The same tab puts Unity's built-in font back if you would rather ship no font at all.

How the cutting works

  1. The picture is rescaled to exactly columns × pieceSize by rows × pieceSize. This is why any source resolution and aspect ratio works.
  2. A border is added so the tabs of the outer pieces have room.
  3. Each piece gets four edges. Edges shared with an already-cut neighbour are mirrored so they interlock; the outside of the picture is straight; the rest are random, so the same level looks different every time it is played.
  4. Each piece is flood-filled from its centre out to its outline and copied from the source pixels.

All of it runs on the CPU through Color32[], one piece per frame, so a large grid never stalls the game.

Performance notes

  • Cutting is spread across frames: a 10×10 grid takes about 100 frames to appear.
  • Piece textures are pieceResolution + 2 × border square, RGBA32. At the default 100 px that is roughly 78 KB per piece.
  • Every runtime texture and sprite is destroyed when the level unloads.
  • Saves are batched and written at most once per second, never per drag frame.

Code map

For programmers who want to go further than the inspector. The code is plain C#, one component per file, every public member documented, comments that say why rather than what.

Assemblies. Corn4Bit.JigsawPuzzle is the puzzle itself; Corn4Bit.JigsawPuzzle.Meta (economy and its screens) depends on it, never the other way round, so the puzzle runs without the meta. Corn4Bit.JigsawPuzzle.Editor holds the window, wizard and inspectors.

The flow of a level. Puzzle Level Selection UI (or your own code) calls PuzzleManager.StartPuzzle(level). The manager opens a PuzzleSession (clock, pieces in place) and the Puzzle Board cuts the picture into Puzzle Piece Draggers, dealt into the Puzzle Piece Tray. Each drop is checked against the piece's slot; the last one raises PuzzleManager.OnPuzzleCompleted. The completion popup shows the result, and Puzzle Meta, listening to the same event, pays the reward and raises PuzzleMetaEvents.LevelRewarded.
