FAQ

General

Which Unity versions does it work with? Unity 6 (6000.0) and newer, on the Built-in, Universal and High Definition render pipelines. The whole game is uGUI, so it does not care which pipeline your game draws with.

Does it work on phones? Yes. Input goes through the standard uGUI event system, so a mouse and a finger behave the same. The layout follows the canvas in both landscape and portrait, and Puzzle Safe Area keeps the HUD clear of notches and rounded corners.

Does it work with the Input System package? Yes, with either backend or both. Puzzle Input Module on the demo scene's EventSystem puts the matching UI module in place at startup. Dropping the prefab into a scene of your own uses whatever EventSystem that scene already has.

Does it need any other asset or package? No. No DOTween, no TextMeshPro, no third-party serialiser, no Resources folder. The animation system is part of the package, and nothing in it references anything outside its own folder.

Can I use it in a game I sell? Yes, under the standard Unity Asset Store EULA. What you may not do is resell or redistribute the package itself, re-skinned or not.

Levels and pictures

How many levels can I ship? As many as you like. The library is a plain list, and the map builds only the nodes on screen, so it scrolls just as smoothly with a thousand levels as with ten.

What pictures can I use? Any resolution and any aspect ratio, in any folder of your project. The only import setting that matters is Read/Write Enabled, and the Level Wizard sets it for you.

How big can the grid be? From 2x2 upwards. Past about 10x10 the wait grows noticeable: cutting runs one piece per frame, and at the default 100 px each piece costs roughly 78 KB of texture memory.

Can the player use a photo of their own? Yes. Build the level in memory and start it:

PuzzleLevel level = PuzzleLevel.Create("My photo", texture, 4, 4, id: "photo-1");
PuzzleManager.Instance.StartPuzzle(level);

The texture has to be readable, which one loaded at runtime through LoadImage already is. Pass a stable id to have its progress remembered, or leave it out for a one-off.

What this package does not do

It is a complete jigsaw game with its own meta, but some things need a service of your own and are not included:

  • A 3D board. Pieces are uGUI images on a canvas.
  • Online multiplayer or cloud saves. The leaderboard ranks the player among bots until you plug in a backend through IPuzzleLeaderboardProvider, and progress is local, though IPuzzleSaveStore is there so you can route it to a backend of your own.
  • A real payment or ad provider. The shop runs on a demo store that charges nothing; purchases and rewarded ads go through two small interfaces so you can plug in Unity IAP, LevelPlay or anything else.
  • A painted world map. The demo map has one meadow with scenery shared by its chapters; give each zone a picture and scenery of your own for a world with distinct places.
  • An auto-solve button. There is a hint, which shows where one piece goes.
  • PSD sources. The UI art ships as PNG.
  • TextMeshPro labels. Text is uGUI Text, which the Apply Font tool restyles in one pass.

The demo pictures under Demo/ are there so the package is playable the minute it is imported. Use your own artwork in a game you publish, and delete Demo/ once you have.

Troubleshooting

"Texture is not readable": enable Read/Write in the picture's import settings, or press the fix button on the level asset.

The level select screen is empty: the PuzzleManager has no level library assigned, or the library has no levels.

Pieces cannot be dragged: the scene has no EventSystem. The scene check on the Setup tab offers to create one.

Pieces cover my HUD: assign a Scatter Area RectTransform on the board that excludes the HUD.

The picture looks stretched: the grid proportions do not match the picture. Use the wizard's suggested grid.
